# Event tree animation — brief for the design

Same treatment as the cut-set piece: designed page, generated content, a wide slider along
the bottom with back / forward, no autoplay.

## The data
`docs/eventtree-data.js` sets `window.EVENTTREE`. Generated by `docs/gen_eventtree_data.py`
from the engine — regenerate after any model change, never edit by hand.

Shape:
- `initiator` — id, label, `frequency` (0.02 per period), evidence class, origin
- `barriers[]` — in the order they act, each with `label`, `fails`, `works`,
  `evidence_class`, `origin`, `authored_by`
- `steps[]` — the five slider stops, in order
- `frames[]` — one per stop:
  - step 0: the initiating event alone, one path
  - steps 1-3: the tree after each barrier is added — 2, 4, then 8 partial paths, each with
    `pattern` (S/F so far), `conditional` and `frequency`
  - step 4: the settled tree — all 8 sequences with `id`, `end_state`, `failed[]` and
    `evidence_class`, plus `end_states[]` totalled and carrying `severity`
- `closure` — 1.0; show it, it is the arithmetic's own check
- `credit` — the method citation, to sit on the page

## The five stops
| step | what appears | paths |
|---|---|---|
| 0 | Grid outage, 0.02 per period | 1 |
| 1 | UPS bridges — fails 0.004 | 2 |
| 2 | Generator starts — fails 0.01 | 4 |
| 3 | Fuel holds — fails 0.005 | 8 |
| 4 | End states, totalled and ranked by severity | 8 |

## What the picture should say
- Success goes **up**, failure goes **down**. The top path is all-success.
- **Write numbers out in full, never as exponents.** 0.0000008 reads; 8e-07 does not, for most
  readers. The data file carries floats; format them as plain decimals to three significant
  figures. The tool's own output now does the same.
- Frequencies span four orders of magnitude (0.0196 down to 0.000000004), so do not scale
  branch thickness linearly by probability — it will vanish. Label instead.
- The worst end state is also the rarest: immediate loss at 0.0000008 against 0.0196 for load
  maintained. Rank by `severity`, never by frequency, or the picture misleads.
- Each path carries the weakest evidence class among the barriers that **failed** on it —
  the numbers doing the work. Same three-colour key as the cut-set piece.
- Worth marking: the generator's 0.01 is `modelled` and the fuel's 0.005 is `asserted`, so the
  leading path to the worst outcome rests on a modelled number and nobody sourced the fuel one.

## Slider
As agreed for the cut-set piece: wide bar along the bottom, back / forward, ticks clickable,
arrow keys bound, no autoplay, `prefers-reduced-motion` respected, no `localStorage`.
Five stops here, so the bar can be segmented per stop with the step name beneath.
